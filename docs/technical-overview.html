04 · Core Logic

Discount Code Generation Flow

The code generation pipeline validates, calculates, stores, notifies, and integrates — all in a single request with async side-effects for email and partner notification.

1

Verify JWT Token

Extract verificationToken from request body. Decode JWT to get schoolId and studentCodeId. Reject if expired or schoolId mismatch.

2

Validate Entity Chain

Confirm school → subject → teacher chain is valid, all active, and the teacher belongs to the subject which belongs to the school.

3

Rate Limit Check

Max 3 codes per (studentEmail + teacherId) in 24h — checked in DB. Returns HTTP 429 with Retry-After header on violation.

4

Price Snapshot

Calculate: originalPrice = teacher.coursePrice, finalPrice = originalPrice - round(originalPrice × discountPct / 100). Snapshot prevents price changes affecting existing codes.

5

Generate Unique Code

Format: EDU-{INITIALS}-{YEAR}-{RANDOM6} using uppercase alphanumeric. Collision-retry up to 5 times. Stored with expiresAt = now() + 48h.

6

Save to PostgreSQL + Redis Cache

Persist DiscountCode record. Cache in Redis: SET code:{codeId} {status} EX 172800 (48h TTL) for fast status lookups.

7

Increment Student Code Usage

Atomically increment studentCode.useCount. If useCount ≥ maxUses, the next generation attempt will be rejected at the verify step.

8

Send Email (async)

Fire-and-forget via Nodemailer: HTML email with code, price breakdown, and expiry. Uses SMTP_HOST/USER/PASS from environment.

9

POST to Partner Webhook (async)

Sign payload with HMAC-SHA256 using PARTNER_WEBHOOK_SECRET. POST to PARTNER_API_URL with retry (3× exponential backoff). Logs to IntegrationLog table.

05 · Security

Security Model

Multiple layers of protection covering authentication, access control, abuse prevention, and data integrity.

🔐 Authentication

  • Admin: JWT signed with HS256, stored in localStorage, sent as Bearer token
  • Student: Short-lived 4h verification JWT issued after double-code check
  • Webhook: HMAC-SHA256 signature on all outbound partner calls
  • Inbound webhooks: HMAC signature verified before processing
  • Passwords hashed with bcrypt (cost factor 10)

🛡 Access Control

  • School-level access code — one per school, admin-generated
  • Student-level code — unique per student, configurable max uses
  • Both codes required before any discount code can be generated
  • Schools without access codes allow open access (backward compatible)
  • Admin middleware on all /admin/* routes via requireAuth()

⚡ Abuse Prevention

  • IP-level rate limiting via express-rate-limit on all public routes
  • Email + teacher combination limited to 3 codes per 24 hours
  • Student code useCount checked atomically before each generation
  • All codes expire automatically after 48 hours
  • Unique constraint on code strings prevents duplicates

🔒 Data Protection

  • All secrets in environment variables, never in code
  • PostgreSQL and Redis not exposed outside Docker network
  • File uploads restricted: max 5MB, image MIME types only
  • Uploaded files stored in named Docker volume, served via /api/uploads
  • Nginx adds X-Frame-Options, X-Content-Type-Options in production
routes/verify.js — double verification logic 
// Step 1: Check school access code
const school = await prisma.school.findUnique({ where: { id: schoolId } })
if (school.accessCode !== schoolCode.trim().toUpperCase())
  return res.status(403).json({ error: 'Invalid school code' })

// Step 2: Check student code + use limit
const sc = await prisma.studentCode.findFirst({
  where: { schoolId, code: studentCode.toUpperCase(), isActive: true }
})
if (!sc || sc.useCount >= sc.maxUses)
  return res.status(403).json({ error: 'Student code limit reached' })

// Step 3: Issue short-lived verification token
const token = jwt.sign(
  { schoolId, studentCodeId: sc.id },
  process.env.JWT_SECRET,
  { expiresIn: '4h' }
)
06 · Deployment

Production Deployment

The entire platform ships as a single Docker Compose stack. One command brings up all services. SSL is handled by Nginx with Let's Encrypt certificates.

nginx/nginx.conf — routing rules 
upstream backend  { server backend:3001; }
upstream frontend { server frontend:80; }

server {
  listen 80;
  server_name edudiscount.com;

  # All API calls → Node.js backend
  location /api/ {
    proxy_pass http://backend;
    proxy_set_header X-Real-IP $remote_addr;
  }

  # All other requests → React SPA
  location / {
    proxy_pass http://frontend;
    try_files $uri $uri/ /index.html;
  }
}

03 · الأمان والتوثيق

نموذج الأمان المزدوج

طبقات متعددة من الحماية تشمل المصادقة، التحكم في الوصول، منع إساءة الاستخدام، وحماية البيانات.

🔐 نظام التوثيق المزدوج

  • رمز المدرسة: كود عشوائي يولده المسؤول، يُوزَّع على الطلاب عبر القنوات الرسمية
  • رمز الطالب: كود شخصي فريد لكل طالب بحد أقصى قابل للتعديل
  • كلا الرمزين مطلوبان لإصدار أي كود خصم
  • عند نجاح التحقق: يُصدر رمز JWT صالح 4 ساعات
  • المدارس بدون رمز وصول: تسمح بوصول مفتوح (متوافق مع الإصدارات السابقة)

🛡 الحماية من الاحتيال

  • تحديد معدل الطلبات على مستوى IP عبر express-rate-limit
  • الحد الأقصى: 3 أكواد لكل (بريد إلكتروني + مدرس) كل 24 ساعة
  • فحص useCount ذري قبل كل إصدار للكود
  • جميع الأكواد تنتهي تلقائياً بعد 48 ساعة
  • قيد التفرد على سلاسل الكود يمنع التكرار

🔑 المصادقة

  • مسؤول النظام: JWT موقع بـ HS256، يُرسَل كـ Bearer token
  • Webhook الخارجي: توقيع HMAC-SHA256 على جميع الطلبات الصادرة
  • كلمات المرور مشفرة بـ bcrypt (معامل التكلفة 10)
  • جميع مسارات /admin/* تتطلب requireAuth()

🔒 حماية البيانات

  • جميع الأسرار في متغيرات البيئة، لا في الكود
  • قاعدة البيانات وRedis غير مكشوفتين خارج شبكة Docker
  • رفع الملفات مقيد: حجم 5MB، صور فقط
  • Nginx يضيف رؤوس الأمان في بيئة الإنتاج
